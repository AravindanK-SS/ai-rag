# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

HR Policy Assistant: a RAG pipeline (LangChain + Chroma + local Ollama `llama3.2`) that has grown, week by week, into an MCP-based tool-using agent. Windows project; use the bundled venv (`venv\Scripts\python.exe`). `requirements.txt` is UTF-16 encoded (and includes `langfuse` for telemetry).

## Commands

- Build vector stores (both chunking strategies): `python ingest.py` → writes `vectorstore/current` and `vectorstore/structure`
- CLI Q&A over a store: `python query.py` (prompts for store name and question)
- Web UI + MCP agent server (port 8080): `python app.py`, then open http://localhost:8080 (serves `index.html`; API: `GET /api/tools`, `POST /api/query`)
- RAG evaluation: `python evaluation.py` (uses `results/questions.json`); LLM judge in `llm_judge.py`
- RAG tests (pytest, needs Ollama + built vectorstores, cases from `results/test_cases_week6.json`): `pytest tests/test_rag.py`; single test: `pytest tests/test_rag.py -k <name>`
- Week 9 MCP verification script: `python test_week9.py` (plain script, not pytest); `python week9_evidence.py <BASE> <SERVER2>` regenerates the Week 9 evidence files from real runs

Ollama must be running locally with `llama3.2` pulled for anything touching `src/llm.py`.

## Architecture

Two layers coexist:

**1. RAG pipeline** (`src/`, `chunkers/`, root scripts). `ingest.py` loads docs (`src/loader.py`, data in `data/`), chunks them with `chunkers/current_chunker.py` vs `chunkers/structure_chunker.py`, enriches metadata (`src/metadata.py`), embeds (`src/embedding.py`) and persists to Chroma (`src/vectordb.py`). `src/retrieval.py:search` is the shared retriever (k=5 in the web app after Week 5 error analysis). `src/agent.py`, `src/workflow.py`, `src/tools.py` hold the earlier HR agent framework.

**2. Dynamic MCP agent** (Week 9). `src/mcp_agent.py:MCPAgent` reads `config/mcp_servers.json`, spawns each server as a stdio subprocess via `src/mcp_client.py:MCPClient` (JSON-RPC over stdin/stdout), and builds `tools_registry` from `tools/list`. No tools are hardcoded in the agent — adding a server is a config-only change (`"command": "python"` is rewritten to `sys.executable`). The model runs in the host: `MCPAgent.run` sends the discovered schemas to Ollama (`src/ollama_chat.py`, stdlib REST, native tool-calling) and loops on tool results; if Ollama or the model is unavailable it falls back to a schema-driven planner (`_plan_from_schemas`) and records the mode in the trace. MCP resources (e.g. the handbook) are attached as context, not exposed as tools. Run the agent with `python -m src.mcp_agent [config] [query]` (not as a script path); set `MCP_AGENT_NO_LLM=1` to force the fallback.
- Servers in `mcp_servers/`: `policy_server.py` (policy search, Server 1), `hris_server.py` (e.g. `get_employee_grade_band`, `get_accrued_leave_balance`).
- `mcp_servers/gateway.py` is a bonus gateway (`config/mcp_servers_gateway.json`) that spawns both servers, builds its routing table from their `tools/list`, writes `audit.log` (caller, tool, employee id), and enforces scoped tokens via the required `GATEWAY_TOKEN` env var (no default; `SCOPED_LEAVE_ONLY_TOKEN` is denied `get_employee_grade_band` with a "Recoverable Error").
- `config/mcp_servers_single.json` = policy server only, used by `test_week9.py` for the before/after tool-discovery comparison.

Server subprocess paths in configs are relative (`mcp_servers/...`), so run everything from the repo root.

`Week5_Error_Analysis_Report.md` records the Week 5 taxonomy; `agent_diff.txt`, `config_diff.txt`, `tool_counts.txt`, `wire.json`, `error_before_after.md`, `risk_note.md` are Week 9 evidence artifacts generated by `week9_evidence.py`.
